## Historical limitation

The original v29 commit `fac79e4cf1731e124f5fb584df5f941db8d7fbad` is not this
wire contract. v31 renumbered registration fields and v33 replaced validation
fields without changing the protocol revision. Those older layouts cannot be
claimed compatible merely because their version field is 1. On 2026-10-17 the
operator approved `0f18950` as the supported previous contract, explicitly
excluding those incompatible pre-v33 layouts. Revision 1 is not sufficient
evidence of compatibility; operators must verify the deployed build's provenance.

## Runtime qualification

Run `just qualify-protocol-runtime` with Docker, OpenSSL and the pinned commit
available locally. CI fetches repository history and runs this gate explicitly.
The build script extracts that exact commit, retains its lockfile and adds only
the `worker-probe.rs` and `schema-probe.rs` example launchers. No predecessor
library or schema is patched.
It builds a host-native probe and prints its source revision and binary SHA-256.
The current worker uses the same launcher in a separate build.

The launcher injects host resources rather than invoking Linux-only discovery.
Disposable command fixtures stand in for libvirt/LVM preflight; the daemon uses
its production mTLS listener, RPC service and migrated PostgreSQL stores. The
test covers legacy/current registration, selected contract persistence,
same-process/session recovery across short and session-expiring listener/service
restarts, unchanged previous-worker drain/deregistration behavior, current-worker
resident cordon/uncordon followed by explicit shutdown-after-idle,
immutable current-worker startup preflight reporting (absent on the predecessor),
and rejection of the previous worker after the floor advances.

The probe is not the deployed Linux executable and its hash is not expected to
match it. The schema probe exercises the predecessor's production migration
entry point: it accepts its original ledger, rejects newer applied migrations
without mutating the ledger, and accepts a pre-upgrade backup restored into a
separate fixture database. This is evidence **against** binary-only rollback,
not permission to delete migration history or restore over live data.

Task execution, artifact/provider recovery, full daemon-process restart and
host rollback remain separate gates. This does not qualify a second physical
worker or restoration of post-backup work.
